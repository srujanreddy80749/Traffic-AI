# AI-Based Traffic Prediction & Congestion-Aware Route Recommendation
### College Project — Experimental System

---

## Overview

This is a college project that builds a working prototype for:
1. **Predicting traffic congestion** using a trained Random Forest model
2. **Recommending routes** using two strategies:
   - **Baseline**: Dijkstra shortest path on *current* travel time
   - **Proposed**: Composite score using *predicted future* travel time + *estimated network impact* of rerouting
3. **Simulating traffic** with a Python macroscopic model
4. **Comparing strategies** across multiple scenarios

> ⚠️ **Important**: All traffic data (road network, vehicle counts, travel times) is **synthetically generated** for demonstration. This system does NOT connect to any real-time traffic data source.

## Quick Start (Windows PowerShell)

```powershell
# 1. Navigate to project folder
cd "C:\Users\User\Desktop\traffic ai"

# 2. Install dependencies
pip install flask pandas scikit-learn networkx numpy

# 3. Run the app
python app.py

# 4. Open browser at:
#    http://127.0.0.1:5000
```

**First run**: The app generates the synthetic dataset (~5,000 records) and trains two Random Forest models. This takes ~10–15 seconds. Subsequent runs load models from disk instantly.

## ML Model Details

**Classifier** — Predicts traffic level (Low / Medium / High)
- Algorithm: `RandomForestClassifier` (150 trees, max_depth=12)
- Features: hour, day_of_week, vehicle_count, weather, accident, road_capacity, congestion_ratio
- Evaluation: Accuracy, F1-score (weighted) on 20% test split

**Regressor** — Predicts travel time (minutes)
- Algorithm: `RandomForestRegressor` (150 trees, max_depth=12)
- Evaluation: MAE, RMSE, R² on 20% test split

**Data**: Synthetic — generated by `data/generate_data.py` using domain rules (rush hours, weather effects, BPR). NOT real-world measurements.

## Routing Model

The road network has **8 nodes** (A–H) and **14 edges**.

Travel time on each edge uses the **BPR (Bureau of Public Roads) function**:

```
t(v) = t₀ × (1 + 0.15 × (v/c)⁴)
```

Where: `t₀` = free-flow time, `v` = current vehicles, `c` = capacity

**Proposed strategy composite score**:
```
score = predicted_future_time + 0.5 × rerouting_impact
```

Where `rerouting_impact = BPR_time_with_extra_vehicles − BPR_time_current`

## Simulation Model

- **Type**: Python discrete-time macroscopic (NOT SUMO)
- **Why not SUMO**: SUMO requires network files (`.net.xml`), route files, and complex setup. A documented Python simulation was chosen for simplicity and transparency.
- **Time step**: 1 minute
- **Metrics**: avg travel time, avg waiting time, total network delay, max congestion

Results show actual measured simulation output. The proposed method does **not always win** — results depend on demand level, weather, and network state.

---

## Known Limitations

1. **No real-time data** — all values are simulated
2. **Synthetic training data** — ML model should not be deployed for real predictions
3. **Small network** (8 nodes) — city-scale results would differ
4. **Macroscopic simulation** — no individual vehicle behaviour, no traffic signals
5. **Simplified rerouting model** — assumes all diverted vehicles take one alternative route
